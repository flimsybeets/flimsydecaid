# FlimsyDecaid

A Decaid skin for a Decent DE1, built for someone with a lot of profiles.
Svelte 5 + TypeScript + Vite. Static build; Decaid serves it and the skin
talks to Decaid over REST and WebSockets on port 8080.

## Commands

```bash
npm run dev                 # dev server (mock data unless a gateway is set)
npm run check               # svelte-check type check
npm test                    # vitest unit tests (pure logic in src/lib)
npm run package             # build + release/flimsydecaid-<version>.zip
npm run install:tablet -- <tablet IP>   # package + install on the tablet over Wi-Fi
```

Dev URLs (`src/api/config.ts`):
- `http://localhost:5173/?mock=1` simulated machine, scale, profiles, beans
- `http://localhost:5173/?gateway=<tablet IP>` real Decaid on the tablet (remembered)
- `?gateway=` clears the remembered gateway. Open `http://<laptop IP>:5173` on the tablet itself to test touch.

Run `npm run check && npm test` before committing.

## What the skin does

- Top tabs: Home, Profiles, History, Beans, Settings. Top right: machine status, then a Sleep / Wake button (`PUT /machine/state/sleeping|idle`), offered only while the machine is idle, heating or asleep.
- **Home is a wizard**: big category tiles → profiles in that category → brew panel to pick a bag and set grind, dose, yield, temperature → Start shot. Each profile tile in a category shows a small graph (`MiniGraph`, `lib/miniGraph.ts`, 100×40 box, 0–12 scale, same series colours): a **Last shot / Plan / None** switch in the category header (`theme.tilePreview`, default Last shot) picks the last real shot with that profile (by title; pressure, flow and weight scaled to fit; fetched one title at a time through `app.wantPreviewShot`, cached per session and refreshed after a pull), falling back to the plan when there's none, or the planned pressure/flow targets drawn dashed (`profileCurve`), or nothing. Pressing and holding a profile (500 ms, `use:longpress` in `src/actions/longpress.ts`; the tile sinks while held and the lift is not treated as a tap) opens it in the profile editor. Once a profile is chosen the brew panel takes the whole Home area (the profile list is hidden) in two columns at 960×600, so nothing scrolls: left = bag list (scrolls inside itself if there are many bags), right = dial-in steppers (the Yield label carries the brew ratio, "Yield · 1:2.0", from dose and yield), sync note and Start shot pinned at the bottom. Back (top left, "‹ Profiles") returns to the profile list with nothing selected. Tapping the Home tab while already on Home (in a category or the brew panel) goes straight back to the category tiles (`app.homeReset`). Under 760px it stacks into one column, with the bags and dial-in scrolling and Start shot pinned. While the on-screen keyboard is open (`html.kb-open`, typing a number) the panel shows only the dial-in steppers (head, bags, source line and Start shot hidden, the steppers scroll if needed), since the keyboard leaves too little height for both columns. **Which bag it starts on** (`startBag` in `lib/defaultBag.ts`): the bag a Brew this again asked for → the profile's default bag → the bag last used with this profile (newest dial-in `updatedAt` for it) → the bag on the machine → the newest open bag; only open bags count. The bag list ends with **Don't track** (freezer doses, samples): no bag is selected, so the workflow's `beanBatchId`/`coffeeName`/`coffeeRoaster` go out as null, nothing is written to any bag, the shot comes off no bag's weight, and the source line reads "Not tracked: nothing is saved to a bag"; its steppers start from what was last used untracked with that profile this session (`app.untrackedDialIn`, memory only), else the profile's own values. It's also where the panel starts when there are no open bags. A small **Set as default** button beside the Bag heading (shown when there's more than one bag) makes the selected bag the profile's default; it then reads ★ Default and tapping it again clears it, and the bag gets a Default tag. A **Last shot** button beside the dial-in source line (shown only when such a shot exists: `app.lastShotIdWith`, asked 300 ms after the profile/bag settles and again after each pull) opens `LastShotDialog` (a wide `Modal`): the newest shot with this profile (by title) and the selected bag (`app.lastShotWith` → `GET /shots?profileTitle=…&beanBatchId=…&limit=1`, then `GET /shots/{id}`), with its grind, dose, out, ratio, time, temperature, rating, notes and graph (touch to read values), and **Use these settings**, which puts that grind, dose, yield and temperature back on the steppers (then the normal auto-load and dial-in rules apply). No Load button: the panel puts its profile, bag and dial-in on the machine by itself, 600 ms after the last change (one request per burst, sends serialised, duplicates skipped, nothing sent mid-shot). The dial-in is written to the bag only when it changed or a shot is started with it, never just from opening the panel (that would reorder carry-over). Beans on the scale are checked against the dose (`doseCheck` in `lib/guide.ts`): a meter above Start shot goes amber with how much to add, green within ±0.1 g, coral with how much to take out; it stays hidden for an empty scale or anything over 1.5× the dose, like a cup.
- **Categories are for organising only.** They never affect settings. Create/edit in `CategoryDialog` (name, colour, icon, move earlier/later, delete; Edit on the category page). Deleting a category never touches its profiles.
- **Guide me** (last tile on Home): set to one profile + one coffee (Change on the tile; "Edit steps" in the setup dialog). Uses the coffee's newest open bag and its dial-in and loads it onto the machine on open. The steps are **data** (`lib/workflow.ts`): a `Workflow {version:1, name, steps}` of `WorkflowStep {id, template, title, body, label, items?, timer?}`, saved in KV `guideWorkflow` (missing/junk = the edition's first preset; `normaliseWorkflow` keeps exactly one pull, done last, smart steps at most once, unique ids, caps). Smart templates follow the scale or machine: `weigh` (live scale, green within ±0.1 g, add/take-out amounts, Tap to connect runs `scanForScale`), `grinder` (shows the grinder's name when Decaid knows it), `grind` (ordered sub-list), `pull` (Start shot, or wait for the group head on GHC), `rinse` (you press flush; follows the machine into `flush` and out), `steam` (same, for `steam`; `app.guideTemplate` stops App showing the steam `ActivityView` over it, like flush for rinse) and `done` (summary). Plain templates (spray, wdt, distribute, funnel, basket, tamp, puckscreen, paper, minerals, knock, shake, custom) show title/body/items and an optional timer (start/countdown); library entries can carry a default `timer` (`shake` "Shake it" = 15 s, copied onto the new step by `libraryStep`; in no preset). Back works up to and including the pull. Titles and bodies can use `{dose} {beans} {coffee} {grind} {source} {start}`. **Steps editor** (`StepsEditor`, wide Modal, a draft until Save): Start from a preset (confirm first), move up/down, remove (not pull/done), edit title/body/rail label/items/timer, per-step photo (Take photo / Upload photo + `PhotoCrop`, KV `guidePhoto:<stepId>`, deleted when the step goes), add from the library (smart ones only while absent) or a custom step, Export (copy JSON; selectable textarea fallback) and Import (paste, validated, notes shown). **Presets**: shared ones in `lib/workflowPresets.ts` (Simple = public default, WDT and puck screen, Milk drinks); the personal "FlimsyBeets" preset in `src/edition/presets.ts` is the original 13 steps and copy and is the personal default. **Art**: `GuideArt` picks the step photo, else the edition's scene for the template (`EDITION.guide.scenes`; personal = `src/edition/guideScenes.ts`, generated by `npm run art:guide`, keys mapped dial→grinder, start→pull, CSS in `src/edition/guideArt.css` scoped `.art.set-flimsy`), else the shared generic scene, else `StepIcon`. Root class `art set-{id} {key} ws-{state}` (+`on`); live overlays by data: `scene.lcd` draws the weight in dot-matrix, `scene.num` the grind pill, the dial arc comes from `dialArc`. Personal art (`scripts/guide-art`): "frosted glass objects" modelled in millimetres and projected orthographically (yaw −32°, elevation ~20–26°; `geo.cjs`), shared objects in `objects.cjs` (Bookoo Themis Mini with the live weight on its left display, dosing cup, espresso cup, naked portafilter with convex basket and marbled purple/black handle, grinder, Weber-style catch cup, DE1 with the group head controller: water 12, steam 3, brew 6, flush 9), framing from measured bounding boxes (`frames.json`, `measure.cjs`, needs Playwright). **Generic art** (`scripts/generic-art/`, self-contained, shares no code with `scripts/guide-art/`): `npm run art:generic` writes `features/guide/genericScenes.ts` (lazy chunk, ~240 kB raw) and `genericArt.css` holds its animation; scenes weigh, spray, grinder, grind, wdt, distribute, funnel, basket, tamp, puckscreen, paper, minerals, pull, knock, rinse, steam, done, shake with brand-neutral objects (plain square scale, dosing cup, conical grinder with a big setting dial, straight-walled basket in a black-handled bottomless portafilter, flat tamper, dropper bottle, milk jug, knock bin, DE1, cobbler shaker and a tumbler with ice in `shaker.cjs`); `steam` shows the jug lifted and tilted 21° towards the wand (spout on the wand side, milk level inside, wand tip dipped off-centre with swirl rings and puffs); `shake` is a held shaker pumped along its axis (`.k-shaker`, with `.k-mline`/`.k-spark` as `.fx`) beside an iced-espresso glass; gradient ids prefixed `gn`, CSS scoped `.art.set-generic.<key> .k-…`, keyframes `gn-`; `weigh` exposes `lcd`/`lcdAt` and `k-beans`/`k-fall`, `grinder` exposes `num` and `.k-dial`/`.dial-arc`, `rinse` water shows only with class `on`; framing from `frames.json` (`node scripts/generic-art/measure.cjs`, then build). Both sets: no SVG/CSS filters or drop shadows, CSS-only animation (transform/opacity/dashoffset) keyed on `k-*` classes, static and complete under reduced motion (`fx` parts hide). Mock helpers: `__flimsyMock.disconnectScale()` (a scan takes 1.5 s to reconnect), `setWeight(g)`, `pressFlush()`, `pressSteam()`.
- **Dial-in is per bag + profile.** Each bag remembers grind, dose, yield and temp offset for every profile used with it.
- **Bottom bar** (always visible): scale name, weight, connection (tap to tare, or to scan when disconnected); water and puck temps; a small tank glyph with the water level in mm (amber at or below the refill level, coral when the machine state is `needsWater`; the fill is a `transform` only); steam heater on/off with live steam temp. Tapping steam opens the steam modal (heater toggle, temperature, flow).
- **Preheat, flush and steam views** (`lib/activity.ts`) follow the machine's own state, so they show when the group-head or machine buttons are used. Entering `espresso` opens the shot view straight away with "Heating up · 2.6° to go" (puck short of target by more than 1.5°), then "Almost there", then "Starting" once the substate reaches preinfusion/pouring, a dim clock counting the heating seconds, the live water and puck temperatures against their targets (puck turns green within 1.5°), and Stop, until preinfusion starts the graph (stopping before it ever pours closes it). `flush` and `steam` get `ActivityView` (elapsed against the rinse time or steam max run time, flow and temperatures, Stop = request idle) and close when the machine leaves the state. While Guide me is open its own rinse step covers the flush, so only steam is shown over it. All three join the shell `covered` condition.
- **Shot view** takes over while pulling and stays until "Done". While pouring, four car-style dials sit in one column left of the graph, full height under the title bar (vertical label, reading bottom to top, left of each dial; dial size is measured from the column height; under 700px wide it falls back to a row above the graph): flow in (machine, ml/s, with target), flow out (scale `weightFlow`, g/s), pressure (with target, red zone from 10 bar), and water + puck on one dial (thin coral and thick gold needles, both targets). The dial for the pump the machine is controlling (Pressure or Flow in) gets a glowing rim ring in its series colour: `PumpTracker` in `lib/pumpMode.ts` reads the nonzero snapshot target, falls back to the profile step's pump (`profileFrame`) when both or neither show, holds the last answer through gaps and needs two agreeing frames to switch; the ring is a static gradient on `Gauge`'s `.face::after` whose opacity transitions, no filter. Dials hide when the shot ends and the graph takes the full width. The graph re-renders on every machine frame and every scale frame (`ShotRecorder.onScale` moves the newest sample's weight), with no throttling or transitions. The target yield is a bold dashed line on the graph with its value in a pill. Temperatures get their own panel under pressure/flow/weight.
- **History**: shot list grouped by day (filter chips per open bag) beside the selected shot's numbers and graph. Refetches after a pull ends. Touching or dragging on the graph (`ShotChart` `scrub` prop, History only; the live shot view leaves it off so it adds no per-frame work) shows a cursor line, a dot on each series and a readout of time, pressure, flow, weight, water and puck with targets, flipping side near the edges; it stays after lift until a tap outside or another drag (`touch-action: pan-y`, so vertical scroll still works). Lookup in `lib/scrub.ts`. **Brew this again** (selected shot) opens the same `BrewPanel` over History with that shot's profile (matched by title and step shape to a lineage, newest version used), its bag if still open, else the newest open bag of the same coffee with a note, and the shot's grind, dose, yield and temperature offset (`planBrewAgain` in `lib/brewAgain.ts`). The panel puts them on the machine through the normal auto-load but writes nothing to the bag until a value is changed or a shot is started; Back returns to History. Beans' per-bag **Shots (n)** button sets `app.historyBag` and opens History filtered to that bag (read once at mount; a finished bag gets its chip too). Delete shot offers "Give back 18 g to the bag" (ticked) when the bag's ledger holds that shot.
- **Profiles tab**: every profile (newest version) with category chips, Edit, Duplicate and a primary Brew button. Duplicate opens the editor on an unsaved copy titled "… copy" (`copyProfile` in `lib/profileEdit.ts`, passed as `app.editSeed`); Decaid only stores it once a step or target differs, since ids hash the execution fields. Brew shows the same `BrewPanel` over the list (local state in `Profiles.svelte`); Back (‹ Profiles) returns to the list with nothing selected.
- **Profile editor** (Profiles tab: New profile / Edit, or Edit in BrewPanel): full screen, one scrolling page under a fixed title bar (chart, then a sticky step strip, then step settings in as many columns as fit beside the profile panel; stacked under 820px). The tablet is about 960×600 CSS px: check layouts there, not just 1280×800. Planned-shape chart (pressure/flow targets with smooth ramps, exits, limiters, temperatures in their own lane, last real shot faint behind), step strip, every step setting visible, profile panel (stop at weight/volume, count-from step, tank preheat, type, author, notes, categories, checks). Undo/redo (Ctrl+Z / Ctrl+Shift+Z, held steppers coalesce), tap a number to type it, DE1-limit warnings that don't block, discard confirmation. Pure logic in `lib/profileEdit.ts`.
- **Visualizer** (Settings, History): Decaid's bundled `visualizer.reaplugin` does the uploading itself on shot events once it is enabled and signed in. Settings shows plugin on/off (`POST /plugins/{id}/enable|disable`) and whether it answers (`status`), username and password (`POST /plugins/{id}/settings`; the password comes back only as `{isSet}` and is never shown, a blank field keeps it), and the Upload shots automatically toggle (`AutoUpload`, default on). "Save and sign in" checks typed credentials with the `verifyCredentials` endpoint. History marks uploaded shots (↑V, the plugin stamps `annotations.extras.visualizerId`) and offers Upload to Visualizer (`POST /plugins/{id}/upload {shotId}`) for the rest while the plugin is on. The skin never talks to visualizer.coffee itself.
- **Bag weight counts down.** When a pull ends and Decaid has stored the shot, `app.settleShot` takes the shot's dose (`annotations.actualDoseWeight`, else `context.targetDoseWeight`) off its bag's `weightRemaining`, clamped at 0. Only shots from that pull (timestamp after it began) are considered, so a reload never re-counts old ones. A shot counts only if it poured at least 5 s or put 5 g in the cup (`lib/bagWeight.ts`). Never twice: the bag carries its own ledger, `extras.flimsydecaid.used` = the last 20 `{id, g}` (grams really taken, after the clamp), newest first; weight and ledger go out in the same batch PUT, so they can't disagree, and the bag is re-read just before so another tablet's write is seen. Deleting a shot can give `g` back (capped at the bag's size) and drops it from the ledger; shots older than the ledger simply offer no give-back.
- **Add a bag** starts on "A new coffee" (the Coffee select also lists "Another bag of …" for each open coffee). Under Roaster and Coffee name, chips offer roasters you've bought from before (`roasterSuggestions` in `lib/roasters.ts`: every coffee incl. finished ones, case/spacing-insensitive, most coffees first then most recent, narrowing to word-starts then substrings of what's typed, exact match hidden, max 6); tapping one fills Roaster and moves to Coffee name (mousedown is prevented so the keyboard doesn't flicker).
- **Photos and colours belong to the coffee, not the bag.** Edit coffee: Take photo / Upload photo / Crop photo / Remove photo; Add a bag offers "Photo of the coffee (optional)" with Take photo (live front camera, else the system camera via a `capture` input) and Upload photo (files/gallery picker, no `capture`) side by side, only for a new coffee or one without a photo, and saves it on the coffee. After taking or choosing one `PhotoCrop` shows a crop step: the picture fills the area, a free-aspect frame (starts at the centre 80%) has 48px corner handles and drags as a whole, everything outside is dimmed. Reset / Cancel / Use photo; the crop is drawn on a canvas straight to the 900px JPEG (`toJpegDataUrl(..., crop)`, maths in `lib/crop.ts`). Bags used to have their own photos (KV `photo:<batchId>`): once ever (after the screensaver loads; KV `photosMoved` = true when done) `app.moveBagPhotos` gives each coffee without a photo its newest bag's photo, reading one key at a time. `app.beanPhotos`: missing = not loaded, null = none; a load never overwrites a save or remove that finished meanwhile. Add a bag offers the photo only once the coffee is known to have none (and turns the camera off if you switch to one that has), and if the bag is added but the photo upload fails it says so and Save becomes Done, so the bag is never added twice. **Coffee colour** (`lib/bagColour.ts`, on a 64×64 copy from `lib/photo.ts`): k-means groups the pixels into up to 10 colour patches (seeded from the busiest cells of a coarse histogram, so it's deterministic; centre pixels weigh more since the crop puts the subject there), and each patch scores chroma (distance from grey, so dark browns and near-whites aren't "saturated") × how usable its lightness is × size (square root up to 30% of the picture); patches under 1.5%, or with chroma under 0.045 or under 11% of their brightness, are not colours. The winner is shown true to the photo, only lifted to HSL lightness 0.48–0.72 and saturation ≥ 0.25 (`displayColour`). Edit coffee offers the photo's colours as swatches (`colourChoices`, automatic pick first) plus None (`app.setCoffeeColour`; a new photo recomputes unless a colour was picked with it). Computed when a photo is saved and backfilled when a photo with no entry loads; writes are batched 600 ms and merged with a fresh read of the KV document. The colour is the coffee card's left edge, tint and photo frame on the Beans page, and every bag of that coffee shows it (`app.coffeeColours[bag.beanId]`) as a left edge on BrewPanel's bag buttons, which also show the coffee photo. Beans cards are compact so two rows of coffees fit at 960×600: 64px coffee photo beside the name, and each bag one row of roast/left info with Shots / Edit / Finished (wrapping below on a narrow card).
- **Editing and deleting** (all destructive actions go through `ConfirmDialog`): coffees (`CoffeeDialog`: edit; Remove = archive coffee + its bags), bags (`BagDialog`: roast date, weight, left, frozen, reopen, delete for good + any old photo key), profiles (editor → Delete profile = every version `hidden`, out of categories and Guide me), shots (History: rate 0–10 + notes via `PUT /shots/{id}` `annotations`, delete), Guide me setup (Remove).
- **App background** (Settings → Theme options): an optional photo behind the whole skin (KV `appBackground`, picked and shrunk exactly like the screensaver photo; Remove deletes the key), drawn by `App.svelte` as a fixed `.app-bg` layer under everything (z-index −1, above `body::before`'s colour pools) with one **Darken** slider over it: 0–100% black (`toneOverlay` in `lib/background.ts`; stored as `theme.bgTone` −100…0, old positive "lighten" values read as 0), saved 400 ms after the last move, default −45. **Panel colour** (same section, `theme.panelTint`: Dark (default) / Teal / Coffee / Plum) sets `<html data-tint>`, which swaps `--glass-fill-thick` in `styles.css`, the frosted fill of the thick sheets (brew panel, dialogs, graphs). Settings lays its sections out in two independent columns (`.col`), so a tall card leaves no gap beside a short one.
- **Screensaver** (Settings): a photo picked from the tablet's files, shown while the machine sleeps, with a big centred 50% white clock over it (about 65% of the screen width, fixed in place, no drifting; Settings → Screensaver → "Show the clock" turns it off, `theme.clock`, default on). Personal edition only: Settings → Theme options has a "Halloween screensaver" toggle (`EDITION.screensaverExtra`, stored as `theme.halloween`): when on, 4 low-poly 3D ghosts (white-to-lavender, flat-shaded, angry blue eyes, fanged grin, two pointed arm flaps, tail wisp) wander over the photo instead of the clock. No WebGL: `npm run art:ghost` (`scripts/ghost-art/build.cjs`) models the ghost once in 3D, projects it orthographically with a fixed light and back-face culling at 24 yaw angles (face drawn as decals dropped onto the front facets, so it turns with the body and hides when the ghost faces away) and writes `src/edition/ghostFrames.ts`, a lazy chunk (drawn by `src/edition/Ghosts.svelte`) loaded with the screensaver as `<symbol id="gf0..23">`. At runtime one rAF loop (~30 updates/s, stopped with the screensaver) asks `ghostPose` in `src/edition/ghostPath.ts` for each ghost's offset, bob, lean, opacity and yaw, sets only `transform` and `opacity`, and swaps its `<use href>` when the frame changes. Heading follows travel (side-on, swinging through the front when it reverses), with scheduled full spins and face-the-viewer pauses with a bigger bob; each fades in and out over its cycle. Reduced motion: no loop, front frame, faint. Screen dimmed to a chosen brightness (slider in Settings, 0–100%, default 12, 100 = not dimmed; moving it while the screensaver or Preview is up applies at once; restored after). Off until a photo is chosen. Tap wakes the machine; if it stays asleep, the screensaver returns after a minute. It appears with a 400 ms fade and leaves with a 250 ms fade (`out:fade|global`); a steam/fog transition was tried (v0.2.34–0.2.35) and dropped as too laggy on the tablet, so keep these transitions plain opacity.

## Two editions: this repo (personal) and FlimsyDecent (public)

This repo is the owner's **personal** edition. The public **FlimsyDecent** skin (github.com/flimsybeets/flimsydecent, skin id `flimsydecent`) is exported from it: `node scripts/export-public.mjs <flimsydecent checkout>` copies every shared file, leaves out the personal ones (`src/edition/`, `test/edition/`, `scripts/guide-art/`, `scripts/ghost-art/`, `editions/`, this CLAUDE.md, README, index.html, manifest, release workflow) and lays `editions/public/` over the top (its own `src/edition/index.ts`, README, CLAUDE.md, manifest, title, release workflow; `package.overrides.json` sets the public package name and keeps the public repo's own version). It deletes target files no longer exported and warns about personal names in shared code. Then review, commit and push in the flimsydecent checkout (its `main`; bump its own version to release). **By default every change goes to both**: do it here, then export. Changes the owner calls personal-only go in `src/edition/` (or `editions/public/` for public-only ones) so they don't leak. Rules: shared code is brand-neutral (no Bookoo/IKAPE/Weber/Timemore/Grindenstein/FlimsyBeets/Halloween outside `src/edition/` and `test/edition/`), and anything that differs between editions goes behind `EDITION` (`src/edition/index.ts`: `screensaverExtra` (the Halloween ghosts here; none in public, which hides the Settings toggle) and `guide` (presets, scenes)). When an edition-facing interface changes, update `editions/public/src/edition/index.ts` too, and keep `editions/public/CLAUDE.md` in step with this file (minus the personal parts). Internal storage keys stay `flimsydecaid` (KV namespace `flimsydecaid/…`, bag `extras.flimsydecaid`) in both editions, so both skins on one tablet share categories, dial-ins and settings.

## Architecture

```
src/
  api/        the ONLY code that touches the network
    config.ts   gateway resolution (?gateway, ?mock, localStorage, VITE_GATEWAY)
    gateway.ts  Gateway interface + HTTP/WebSocket implementation
    mock.ts     in-memory Gateway with simulated telemetry (same interface)
    socket.ts   one WebSocket reconnect policy: exponential backoff + jitter
    types.ts    Decaid API types used by the skin
  lib/        pure logic, unit tested in test/ (no DOM, no Svelte)
    profiles.ts   lineage roots, newest-per-lineage, temperature shift
    dialIn.ts     per bag + profile dial-in storage and lookup
    categories.ts category document in the KV store
    steam.ts      steam heater rules and ranges
    scrub.ts      History graph readout: nearest / interpolated values at a time
    shot.ts       ShotRecorder (live graph) + samplesFromMeasurements (saved shots)
    history.ts    day grouping, ratio, stop-reason wording, shot stats
    screensaver.ts  clock text, fitting the photo under the store limit, dim level
    water.ts      tank level → ok / low / empty, glyph fill, refill range
    activity.ts   which flush / steam view, preparing-to-pour, preheat wording, timer text
    visualizer.ts plugin state, settings parsing (password redacted), shot upload id
    profileEdit.ts  step ops, planned curve, validation, undo history, save rules
    guide.ts      Guide me: setup, bag pick, brew plan, weigh state, step order
    gauge.ts      dial geometry (240° sweep), ticks, temperature dial range
    dialArc.ts    Guide me grinder dial: grind to arc length / ring rotation
    pumpMode.ts   shot view: pressure- or flow-controlled step (highlight ring)
    photo.ts      camera + JPEG downscale
    roasters.ts   Add a bag: roaster suggestions from past coffees
    workflow.ts   Guide me steps as data: templates, library, normalise/validate, edit helpers
    workflowPresets.ts  shared Guide me presets (Simple, WDT and puck screen, Milk drinks)
    grinder.ts    Decaid grinder record → grind stepper step/range/name
  edition/    PERSONAL ONLY (not exported): index.ts (EDITION: screensaverExtra = Halloween ghosts, guide {presets, scenes}), presets.ts (FlimsyBeets), scenes.ts + guideScenes.ts + guideArt.css (personal art), Ghosts.svelte, ghostFrames.ts, ghostPath.ts
  state/app.svelte.ts  single app state (Svelte 5 runes class) + actions
  components/  BottomBar, SteamModal, ShotView, ActivityView, ShotChart, Gauge, Screensaver, Stepper (typeable), Segmented, Modal, ConfirmDialog
  features/    home (wizard + BrewPanel), profiles (+ ProfileEditor, ProfileCurve, StepInspector), guide (Guide, GuideArt, GuideSetup, StepsEditor, StepPhotoField, StepIcon, scenes.ts = SceneSet type, genericScenes.ts), beans (+ AddBag), history, settings
  styles.css   design tokens
```

Rules:
- UI never calls `fetch`/`WebSocket`; add methods to `Gateway` and implement them in **both** `gateway.ts` and `mock.ts`.
- Logic that can be pure goes in `src/lib` with a test.
- Never `structuredClone` Svelte state (proxies throw). Use JSON round-trips or `$state.snapshot`.

## Where data lives (decided)

| Thing | Storage | Notes |
|---|---|---|
| Categories | KV `/api/v1/store/flimsydecaid/categories` | Decaid has no profile tags. Profiles referenced by **lineage root id** |

## Decaid facts that matter here

Source of truth: `assets/api/rest_v1.yml`, `assets/api/websocket_v1.yml` and `doc/Skins.md` in https://github.com/decentespresso/decaid. Clone it and grep rather than guessing payloads.

- **Profile ids are content hashes.** Editing a profile creates a new id with `parentId` → old id. Key anything long-lived by `lineageRoot()`. Show `latestPerLineage()` in lists.
- **Saving profiles** (`saveProfile` in `lib/profileEdit.ts`): the id hashes only execution fields (version, beverage_type, steps, tank_temperature, target_weight/volume, count start), not title/author/notes. `POST /profiles {profile, parentId}` makes a version; if the hash exists Decaid returns the existing record unchanged, so a title/notes-only edit is then `PUT /profiles/{id}` (refused for Decaid's defaults). Never `PUT` an execution change: it replaces the record under a new id and orphans the lineage. Never hide old versions: `lineageRoot` walks visible profiles only.
- **Brew temperature lives in profile steps**, not the workflow. Apply a bag's offset with `shiftTemperature()` and send the shifted profile inline in `PUT /workflow`. Never save it as a new profile.
- **`PUT /workflow` deep-merges.** `targetYield` and every `steamSettings` field must never be `null` (400). Other context fields accept `null`, which clears them. `targetYield` 0 = stop-at-weight off.
- **Steam heater = temperature.** `steamSettings.targetTemperature` 0 = off; DE1 range 135–160 °C (Bengle 165). `duration` is max run time only. Live boiler temp is `steamTemperature` on the machine snapshot. Steam flow range in `lib/steam.ts` (0.4–2.5) is a guess; verify on the machine.
- **Temperatures**: `mixTemperature` = water entering the group ("Water", thin coral line); `groupTemperature` = group head sensor, closest to the puck ("Puck", thick gold line). Always °C. During hot water on a classic DE1, `mixTemperature` is not the outlet temperature.
- **Sockets**: `ws/v1/machine/snapshot` (~10 Hz) stays open while no machine is attached and re-binds across a machine power-cycle. `ws/v1/scale/snapshot` sends `{status}` frames on open/connection change and weight frames while connected; a status frame is not a 0 g reading. Use `ws/v1/devices` for connected/disconnected. Reconnect only on socket close. Decaid rate-limits upgrades per client (429), hence backoff with jitter.
- **The machine zeroes the inactive pump target** (targetPressure is 0 on flow steps); `ShotRecorder` drops those so dashed targets break instead of diving to 0.
- **Don't hammer the API.** Decaid doesn't debounce and drops requests that queue too long. Debounce anything sent on change (BrewPanel: 600 ms); profile edits stay drafts until Save.
- **Camera** (`doc/Skins.md` § Live Camera Access): `getUserMedia({video:true,audio:false})` works only from the *installed* skin's `http://localhost:<port>` origin with per-skin consent; never from the dev server or live-edit. Uses the **front** camera (the tablet is mounted facing you): `facingMode: 'user'`, preview mirrored, saved photo not. `AddBag` falls back to `<input type="file" accept="image/*" capture="user">`; Android's camera app may still open on whichever camera it used last.
- **Background reloads**: Decaid unloads the WebView after ~10 min in the background and reloads the skin. Keep anything important in Decaid (KV store, beans, workflow), not in memory. `sessionStorage` doesn't survive.
- **Shots**: `GET /shots` is paginated (`limit` ≤ 100, `offset`, newest first) and has no measurements; `GET /shots/{id}` has `measurements: [{machine, scale, volume}]` covering the whole espresso state, so trim to preinfusion/pouring like the live graph (`samplesFromMeasurements`). `annotations.actualYield` is often null; use the last scale weight. `stopReason` is an open set. `enjoyment` is 0–10.
- **Screen while asleep**: Decaid's wake-lock is auto-managed (screen allowed off while the machine sleeps). The screensaver holds `POST /api/v1/display/wakelock` while showing and `DELETE`s it on close, and dims via `PUT /display/brightness`, restoring the previous `requestedBrightness` (calls are queued so a quick close can't leave it dark). Request bodies are capped (1 MiB for the KV store, `bounded_request_body.dart`).
- **Water levels**: `ws/v1/machine/waterLevels` sends `{currentLevel, refillLevel}` in mm of water height (no tank height is given, so the glyph assumes a nominal 50 mm full; the number shown is always mm). `POST /api/v1/machine/waterLevels {refillLevel}` sets the warning threshold (truncated to an integer, 202). `doc/Skins.md` shows `warningThresholdPercentage` there; the REST spec and handler use `refillLevel`, so we follow those. Machine state `needsWater` means empty.
- **Plugins**: `GET /plugins` lists `{id, loaded, autoLoad, ...}`; `GET|POST /plugins/{id}/settings` (secure values redacted to `{isSet}`; POST omits = keep, null = clear, and reloads a loaded plugin); `POST /plugins/{id}/enable|disable`; `GET|POST /plugins/{id}/{endpoint}` calls a declared endpoint (Visualizer: `status`, `upload`, `verifyCredentials`, `forwardSyncStatus`).
- **Settings**: Decaid's bundled settings plugin lives at `/api/v1/plugins/settings.reaplugin/ui?backName=<EDITION.name>`.
- **GHC machines**: the Group Head Controller owns shot start. `GET /api/v1/machine/info` → `GHC: true`; read each time the machine connects. BrewPanel then shows "Start the shot on the group head" instead of Start shot. `?mock=1&ghc=1` fakes it.
- **Scale connection**: Decaid connects scales itself (`ConnectionManager`): with a preferred scale (`preferredScaleId`, saved automatically on a successful connect) it runs a background watch, without one a single scan ~3 s after the machine connects. On Android that watch can stall (more than 5 scan starts in 30 s are swallowed), so the skin also hunts (`lib/scaleHunt.ts`, `app.updateScaleHunt`): while the machine is connected and awake, no scale is connected and no shot is running, it sends a scan after 5 s, then 10, 20, 40 s … doubling up to every 5 min, for as long as it takes (restarting at 5 s whenever that state begins again or the tablet screen comes back on), the same pattern Bestpresso (github.com/xinghendri/bestpresso, `sleepControl.ts`) uses. Every scan, automatic or tapped, is `{command:'scan', connect:true, connectPreferredScaleEarly:true}` (REST `/devices/scan?connect=true&connectPreferredScaleEarly=true`), which connects the preferred scale the moment it's sighted instead of after full discovery; a plain scan also cancels Decaid's own preferred-scale reconnect. A tap while a scan runs is ignored.
- **Decaid never decrements `weightRemaining`** (its `decrementBatchWeight` is never called), so the skin does it after each shot, tracked by the per-bag ledger (see Bag weight counts down). `GET /bean-batches/{id}` is used to read a bag fresh before that write.
- **Archived beans and bags are hidden by default**: `GET /beans` and `GET /bean-batches` need `?includeArchived=true` (dial-in carry-over from a finished bag, "Show finished bags", old shots' bag names all depend on it). Filter `archived` in the UI instead.
- **Batch PUT merges top-level fields only**: `extras` is replaced whole, hence `withDialIn` copies other keys. Missing KV keys answer 200 `null`, not 404.
- **Layers**: profile editor 25, guide 27, shot view and flush/steam views 30, modals 60/61, screensaver 100. Full-screen views with oversized decoration use `overflow: clip` (not hidden), so focus/scrollIntoView can't shift them.
- **On-screen keyboard** (`src/keyboard.ts`): while a text field has focus and the visible area shrinks, `<html>` gets `kb-open` and `--kb` = the part of the page the keyboard covers (0 when the WebView resizes instead). The bottom bar hides, modals fill all the room above it with a slim title and buttons, Enter moves to the next text field and on the last one presses the dialog's last action button (stepper tap-to-type boxes excluded: Enter just confirms the number), the profile editor folds its chart and step strip, and the focused field is scrolled into view. Any new full-screen form should honour `--kb` / `kb-open` too.
- **Glass + scrolling**: a `.glass` element must not be the scroll container (its `::before` rim scrolls away). Scroll an inner element instead, as BrewPanel and Modal do.
- **Releases**: `.github/workflows/release.yml` publishes the installable zip whenever `main` gets a push (a merged PR) whose `package.json` version has no `v<version>` tag yet: it tags that commit and publishes the release itself. So bumping the version in a PR and merging it is the release; merges without a bump only build. A pushed `v*` tag or a manual run on `main` work too. Claude sessions can't push tags (proxy) or start workflows (the GitHub app lacks Actions write), which is why it hangs off the merge.
- **Skin updates**: Settings → Connection has "Check for skin updates": `POST /api/v1/webui/skins/update` (Decaid re-fetches every installed skin from its source and installs newer ones; 500 with a plain-language error on failure), then `GET /webui/skins/<EDITION.skinId>` for the installed `version`, compared with `__APP_VERSION__` (`lib/skinUpdate.ts`). Newer → "Version X is installed" + Reload to use it (`location.reload()`); otherwise "You're on the latest version".
- **Manifest**: `public/skin-manifest.json`. Keep `id` = `flimsydecaid` forever (it's the install folder and update identity). Version is numeric dot-segments only; `npm run package` stamps it from `package.json` or the `v*` tag.

## Design

Tablet next to the machine, read at arm's length, wet hands.
- Base: deep ink-teal (`--ink`), cream text (`--paper`), over a fixed backdrop of soft colour pools (in `styles.css` on `body`) for the glass to refract. One loud element: the category tiles in riso-label colours (`--cat-1…8`), as tinted glass (78%→52% of the colour, with the 18px frost blur, so an app background shows through softly). Keep everything else quiet.
- **Glass (Apple-style materials), global classes in `styles.css`:** `.glass` (blurred translucent fill, rim light via `::before`, sheen, soft shadow), `.glass.thick` (sheets: modal, brew panel, graphs), `.glass.solid` (bright prominent action, dark text), `.glass.lit` / `aria-pressed|checked="true"` (selected), `.well` (recessed: steppers, inputs). A component's scoped `background`/`color` beats these, so drop them from elements that use the classes. `.glass` needs its `::before` free. Blur cost is unknown on the tablet; `--glass-blur` is the one knob to turn down.
- Font: Sen (bundled via @fontsource-variable/sen, weights 400–800, works offline; don't load it from Google Fonts). No italic, so don't use `font-style: italic` (it would be faked). Tabular figures everywhere.
- Numbers: every Stepper is tap-to-type by default (`inputmode=decimal`, the number pad), as well as −/+.
- Touch targets ≥ 48px (`--touch`), small buttons ≥ 40px, primary actions ~60px+. The whole UI is at 75% of its first sizes (first use on the tablet felt zoomed in); text tokens are a little larger than 75% so they still read at arm's length. Keep new UI on the tokens rather than fixed px.
- **Performance rules** (weak tablet GPU): full-screen overlays (guide, shot view, profile editor) are opaque, so `App.svelte` marks the shell `covered` (`visibility: hidden`, `inert`, animations off) and the guide gets `covered` while the shot view is up (it stays mounted, but skips its scene). Any new full-screen view should join that condition. Blur tokens are `--glass-blur` 12px/140% and `--glass-blur-thick` 20px/140%; buttons, list rows and glass inside glass have no backdrop-filter (rule in `styles.css`), so only sheets, bars, graphs and category tiles blur. Exception: `.glass.frost` (frosted cards that sit straight on the page backdrop, so they stay readable over an app background photo: Home profile tiles and the buttons above them, Profiles rows, Beans coffee cards and the Show finished toggle, the History list and selected-shot panel, Settings sections) keeps a blur (`--glass-blur-frost` 18px, with a slightly whiter `--glass-fill-frost`); the no-blur and reduced-transparency fallbacks name `.glass.frost` too, since its specificity beats plain `.glass`. Don't add `frost` to anything inside another sheet. The page backdrop is `body::before` (fixed), never `background-attachment: fixed`. No `filter`/drop-shadow on anything animated or repainted at telemetry rate. `machine` and `shot` in app state are `$state.raw`, replaced whole each frame: never mutate them in place.
- **Dials** (`Gauge.svelte`): flat frosted disc, fine rim, thin track, soft value arc, thin needles, a marker on the rim per target. Needles are separate SVGs (not `<g>`) so their rotate transition runs on the compositor; a transition on an SVG child cost about half the main thread during a shot.
- Graph colours are fixed across every graph: pressure green, flow blue, weight brown, water coral (thin), puck gold (thick). Targets dashed.
- Copy: plain, sentence case, says what happens ("Start shot", "Save steam settings", "Delete bag").
